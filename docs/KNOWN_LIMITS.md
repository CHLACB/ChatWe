# 已知限制

## 当前已固化的信息

1. 微信 PC 版 3.9.x 主窗口类名候选：`WeChatMainWndForPC`。
2. 可通过 Win32 枚举顶层窗口，返回 `hwnd/title/class_name/pid/visible/minimized`。
3. 可通过 `hwnd` 转 UIA WindowControl。
4. 可恢复最小化窗口、激活窗口、置前窗口。
5. 可使用剪贴板写入文本、`Ctrl+V` 粘贴、`Alt+S` 发送。
6. 当前发送使用单一无鼠标策略 `clipboard_alt_s`：先清空输入框，再剪贴板粘贴，最后 `Alt+S` 触发发送；不循环兜底，避免向输入框重复写入文本。
7. 第一阶段只支持好友私聊，不支持群聊监听、群消息读取或群聊发送。
8. 好友私聊中，已验证 self 头像和时间/system 规则后，剩余可见文本按对方消息 `other` 处理；该规则不用于群聊。

## 尚未固化的信息

以下控件不能凭猜测写入代码，必须先通过本机微信 3.9.12.56 采集：

1. 搜索框。
2. 搜索结果和精确会话入口。
3. 当前聊天标题。
4. 消息区。
5. 更多单条消息系统提示样式，例如撤回、好友验证、风险提示等，需要持续补充到 `message_item.system_text_patterns`。
6. 输入框。

## 当前真实 UIA 能力边界

真实 UIA 驱动已经具备窗口查找、窗口控制、控件树 dump、配置驱动定位和结构化失败提示。没有本机已验证 locator 时，真实发送和读取会明确失败并提示需要采集的控件信息。

在本机微信 3.9.12.56 上，文件传输助手已验证单一无鼠标策略 `clipboard_alt_s` 可真实发送并完成发送后验证。失败时不会再尝试其他兜底，也不会移动鼠标。

切换会话当前使用 `Ctrl+F` 聚焦左侧搜索框，确认焦点确实落在搜索框后再粘贴目标好友名并回车。若焦点验证失败，会停止输入并返回结构化错误。

好友私聊的可见消息读取规则为：右侧自己头像命中的消息标记为 `self`，时间或系统提示标记为 `system`，其余文本标记为 `other`。这使真实好友私聊可以触发 AI；群聊仍然不启用该兜底，避免把群内成员和系统消息混淆。

## Mock 模式

Mock 模式不依赖微信，保留完整主链路：

监听对象 -> mock 对方消息 -> 入库 -> 上下文 -> mock AI -> 发送队列 -> mock 发送 -> 发送后验证 -> 自己消息入库。
