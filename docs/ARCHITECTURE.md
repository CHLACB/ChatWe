# 架构说明

## 1. 总体分层

```text
API层
↓
应用服务层
↓
监听调度层 / 消息采集层 / 上下文构建层 / AI网关层 / 发送队列层
↓
身份验证层 / 消息存储层
↓
微信执行层 / 历史读取层
↓
环境检测层
```

## 2. API 层

职责：

1. 接收前端请求。
2. 做基础参数校验。
3. 调用应用服务层。
4. 返回统一响应。

不做：

1. 不操作微信窗口。
2. 不读微信数据库。
3. 不直接调用 AI。
4. 不写业务流程。

## 3. 应用服务层

职责：

1. 编排主流程。
2. 协调监听、入库、上下文、AI、发送。
3. 保持业务流程集中。

主流程：

```text
监听名单
→ 身份验证
→ 实时消息采集
→ 消息入库
→ 上下文构建
→ AI 网关
→ 发送队列
→ 微信发送
→ 发送后验证
→ 自己消息入库
```

## 4. 监听调度层

职责：

1. 维护监听名单。
2. 轮询监听对象。
3. 运行中先调用微信执行层被动扫描左侧会话列表。
4. 只对有未读/新消息信号的监听对象切换会话并读取可见消息。
5. 将消息交给应用服务层。
6. 异常时暂停当前监听对象。

应用服务会忽略不在监听名单中的实时消息；监听循环只轮询 `listening` 状态的对象。

启动时允许对监听对象执行一次 baseline，读取当前可见消息并入库但不触发 AI。baseline 完成后，无未读/新消息信号时不得调用 `switch_conversation()`，不得激活微信窗口，不得发送 Ctrl+F。

状态只有：

```text
listening 监听中
stopped   未监听
```

## 5. 消息采集层

职责：

1. 将 UIA 控件读取结果转换为标准 `Message`。
2. 生成短期 fingerprint。
3. 去重。
4. 区分 self / other / system。

第一阶段只处理 text。

## 6. 历史读取层

职责：

1. 从本地历史库读取消息。
2. 输出统一 `Message` 对象。
3. 失败时返回错误，不中断实时监听。

当前骨架只提供标准化历史库适配器，不猜测真实微信库表。

## 7. 身份验证层

核心目标：防止串聊、防止错发、防止入错库。

验证点：

```text
入库前验证
发送前验证
发送后验证
```

## 8. 发送队列层

职责：

1. 接收待发送文本。
2. 串行执行。
3. 发送前验证会话。
4. 调用微信执行层发送。
5. 发送后验证。
6. 成功后写入自己消息。

所有微信窗口操作都必须串行。

当前实现中监听器和发送队列共享同一把 Driver 锁，避免轮询读取和自动发送同时抢微信窗口。

## 9. 微信执行层

职责：

1. 找微信窗口。
2. 切换会话。
3. 读取当前窗口会话信息。
4. 读取可见文本消息。
5. 发送文本。

重要原则：

当前仅固化微信 3.9.12.56 主窗口类名候选 `WeChatMainWndForPC`。真实 UIA 驱动必须通过控件采集结果配置搜索框、聊天标题、消息区、输入框等定位器。定位失败时返回结构化错误和采集命令。

## 10. 可扩展点

```text
图片 OCR       → 消息处理扩展
语音转文字     → 消息处理扩展
发送图片       → 发送队列增加类型
群聊规则       → 触发规则模块
多账号         → 环境检测 + 身份层扩展
真实历史库适配 → 新 HistoryReader 实现
真实 AI        → 新 AiGateway 实现
```

## 11. LangGraph AI 网关

当前推荐 AI 实现是 `APP_AI_MODE=langgraph`。它仍然实现 `AiGateway.generate_reply(context, trigger_message)`，因此应用服务层、监听调度层、发送队列和微信执行层不需要知道 LangGraph 的存在。

LangGraph 内部节点：

```text
analyze_intent
→ decide_reply
→ plan_response
→ draft_reply
→ auto_safety_check
→ format_output
```

约束：

1. LangGraph 只负责决策和生成文本。
2. LangGraph 不调用微信 Driver。
3. LangGraph 不写数据库。
4. LangGraph 不创建监听对象。
5. 最终输出仍为 `{"messages":[...],"done":true}`，由应用服务层解析后进入发送队列。
