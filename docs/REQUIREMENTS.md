# 需求 / 要求文档

## 1. 项目目标

构建一个本地运行的微信 AI 自动回复系统：

```text
监听名单 → 实时采集 → 入库 → 构建上下文 → AI生成 → 发送队列 → 微信发送 → 自己消息入库
```

系统不依赖第三方 wxautox4 HTTP API。后端保留自己的 FastAPI API 作为前端入口，后端内部直接调用 Service 和 Driver。

## 2. 第一阶段范围

必须支持：

1. 好友和群聊监听名单。
2. 监听状态：监听中 / 未监听。
3. 文本消息采集。
4. 区分自己消息和对方消息。
5. 自己消息入库，但不触发 AI。
6. 对方文本消息触发 AI。
7. 只回复监听名单。
8. 发送消息自动执行，不人工确认。
9. 发送前校验会话，防止错发。
10. 发送后校验最后一条自己消息并入库。
11. 历史消息只读本地库；失败只提示，不中断实时监听。
12. AI 接口预留，不绑定具体模型。

## 3. 第一阶段暂不实现但预留

1. 图片识别 / OCR。
2. 语音转文字。
3. 发送图片 / 文件。
4. 群聊触发规则。
5. 多账号。
6. 长期记忆和复杂上下文策略。

## 4. 不做的事

1. 不实现微信协议逆向。
2. 不做 Hook 注入。
3. 不读取非本机数据。
4. 不猜测微信控件信息。
5. 不写死微信本地数据库结构。
6. 不让 AI 直接操作微信窗口。

## 5. 防串聊要求

入库前、发送前、发送后都必须进行会话身份验证。

不能只相信 `who` 字符串，因为昵称、备注、群名可能重复或变化。

系统应使用 `ConversationIdentity` 表示会话身份。

## 6. 微信 3.9.12.56 UIA 要求

已确认可作为版本专用策略的信息：

```text
主窗口 ClassName 候选: WeChatMainWndForPC
顶层窗口枚举字段: hwnd/title/class_name/pid/visible/minimized
窗口控制: 恢复、激活、置前
发送动作: 剪贴板写入文本 -> Ctrl+V -> Enter
```

未确认控件不得写死：

```text
搜索框
搜索结果
聊天标题
消息区
单条消息 self/other/system 判定
输入框
```

定位失败必须返回结构化错误，包含缺少的控件、需要反馈的字段和推荐 dump 命令。
